# AI-Driven Development Interview Questions

This document contains interview questions focused on leveraging AI tools (Copilot, Cursor, Code Interpreters) for software engineering.

## Basic (Easy)

### 1. What is AI-Driven Development (AIDD)?
**Answer:** 
**The Core Concept:**
AI-Driven Development is a software engineering paradigm where developers heavily integrate AI tools (like GitHub Copilot, Cursor, or autonomous coding agents) into their daily workflow to write, refactor, test, and debug code.

**Key Details:**
- It shifts the developer's role from writing boilerplate syntax to reviewing, orchestrating, and prompting.
- Code generation, automated test writing, and intelligent code review are core components.

**Example:** Using a tool like Cursor to automatically generate a suite of unit tests for a React component based on a single prompt.

**Reference:** [AI-Assisted Software Development](https://martinfowler.com/articles/exploring-gen-ai.html)

## Additional Depth (Architectural Focus)

### 2. How do you prevent AI-generated code from introducing subtle security vulnerabilities?
**Answer:** 
**The Core Concept:**
LLMs are trained on public repositories, which contain millions of insecure coding patterns. They can easily hallucinate SQL injections, insecure cryptographic algorithms, or hardcoded secrets.

**Key Details:**
- **Defense in Depth:** AI is a co-pilot, not an auditor. All generated code must pass through static analysis tools (SAST) like SonarQube.
- **Prompt Engineering:** Explicitly prompt the AI to use secure practices (e.g., "Write a parameterized SQL query").
- Never blindly accept large blocks of AI code without line-by-line human review.

**Example:** Rejecting an AI suggestion that uses `eval()` in JavaScript and prompting it instead to use `JSON.parse()`.

**Reference:** [OWASP Top 10 for LLMs](https://owasp.org/www-project-top-10-for-large-language-model-applications/)

### 3. What are the limitations of LLM context windows when refactoring large legacy codebases?
**Answer:** 
**The Core Concept:**
An LLM can only "see" a limited amount of code at once (its context window). Large enterprise applications span hundreds of interconnected files, far exceeding this limit.

**Key Details:**
- If you ask an AI to refactor a function, it might break dependencies in files it cannot see.
- **Solution:** Use RAG architectures tailored for codebases (like Cursor's codebase indexing) which use embeddings to pull only the relevant interfaces and function signatures into the prompt.

**Example:** Instead of pasting an entire 10,000 line monolith into ChatGPT, using Cursor's `@Codebase` feature to automatically search for and inject only the files importing the target function.

**Reference:** [Cursor IDE Architecture](https://docs.cursor.com/)

### 4. How does Test-Driven Development (TDD) adapt when an AI is writing the implementation?
**Answer:** 
**The Core Concept:**
In AI-Driven TDD, the human defines the exact specifications and boundary conditions via tests, and the AI rapidly generates the implementation to satisfy those tests.

**Key Details:**
- Human developers focus on writing rigorous, edge-case heavy unit tests.
- The AI is then prompted: "Here are my failing tests. Write the implementation to make them pass."
- This shifts the human role from "typist" to "specifier/architect," ensuring the AI's hallucination is bounded by strict assertions.

**Example:** Writing a Jest test for a complex date parser, running it to watch it fail, and then using GitHub Copilot to generate the regex and logic to turn the tests green.

**Reference:** [Test-Driven AI Development](https://martinfowler.com/articles/exploring-gen-ai.html#test-driven)

### 5. How do you review Pull Requests (PRs) that are 90% generated by autonomous coding agents?
**Answer:** 
**The Core Concept:**
AI can generate hundreds of lines of code in seconds, shifting the bottleneck from code creation to code review. Reviewing AI code requires immense vigilance against "plausible-looking but wrong" logic.

**Key Details:**
- **Focus on Intent:** Ensure the architecture aligns with system design, not just syntax.
- **Check for Hallucinated APIs:** AI often invents libraries or functions that don't exist in the current version of the framework.
- **Run the Code:** Static reading is not enough for AI code; it must be executed and stepped through in a debugger.

**Example:** Noticing that an AI generated `Array.prototype.customSort()` which looks entirely native but throws a `TypeError` at runtime.

**Reference:** [Code Reviewing AI Code](https://github.com/features/copilot)
