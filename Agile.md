# Agile Development Interview Questions

This document contains interview questions focused on Agile methodologies, Scrum, Kanban, and modern software development lifecycles.

## Basic (Easy)

### 1. What is Agile?
**Answer:** 
**The Core Concept:**
Agile is an iterative approach to project management and software development that helps teams deliver value to their customers faster and with fewer headaches.

**Key Details:**
- Instead of betting everything on a "big bang" launch (like Waterfall), an agile team delivers work in small, but consumable, increments.
- It emphasizes collaboration, flexibility, continuous improvement, and high-quality results.

**Example:** Using two-week "sprints" to deliver a working piece of software iteratively.

**Reference:** [Atlassian Agile Coach](https://www.atlassian.com/agile)

---

### 2. What is Scrum?
**Answer:** 
**The Core Concept:**
Scrum is an agile framework that helps teams work together and get work done in a structured, iterative way.

**Key Details:**
- It is based on a set of meetings, tools, and roles (Product Owner, Scrum Master, Developers).
- Development is broken down into fixed-length iterations called sprints.

**Example:** Holding a 15-minute daily stand-up meeting to discuss progress and blockers.

**Reference:** [Scrum.org What is Scrum](https://www.scrum.org/resources/what-is-scrum)

---

### 3. What is the difference between Agile and Waterfall?
**Answer:** 
**The Core Concept:**
Waterfall is a linear, sequential approach where each phase of the project must be completed before the next begins, whereas Agile is iterative and continuous.

**Key Details:**
- Waterfall is inflexible to changing requirements once development starts.
- Agile welcomes changing requirements, even late in development, to provide a competitive advantage.

**Example:** In Waterfall, testing happens at the very end. In Agile, testing happens continuously in every sprint.

**Reference:** [Agile vs Waterfall](https://www.atlassian.com/agile/project-management/project-management-agile-vs-waterfall)

### 4. What is the difference between Story Points and hours when estimating work?
**Answer:** 
**The Core Concept:**
Story points represent a relative measure of complexity, effort, and risk, rather than an absolute time duration like hours. This abstraction helps teams account for varying skill levels, as a complex task takes the same 'points' regardless of whether a senior or junior developer executes it.

**Key Details:**
- Story pointing often uses the Fibonacci sequence (1, 2, 3, 5, 8, 13) to reflect the inherent uncertainty in larger tasks.
- It prevents stakeholders from equating estimates directly to rigid deadlines, fostering a focus on velocity and continuous improvement.

**Example:** 
`A simple UI text change is a 1; migrating a database table with downtime risk is an 8.`

**Reference:** [Documentation](https://www.atlassian.com/agile/project-management/estimation)
